## D9 节点架构（异构传感网）

> 项目核心架构决策，决定了硬件采购清单和简历亮点。

### 节点角色分配

| 节点 | 板子 | 传感器 | 角色 | 简历亮点 |
|---|---|---|---|---|
| 节点 1 | **C8T6** | DHT11 温湿度 | 环境数据采集 | "C8T6 低成本节点" |
| 节点 2 | **C8T6** | BNO055 九轴 | 姿态数据采集 | "C8T6 + 板载融合算法" |
| **节点 3（主）** | **VET6 指南者** | DS18B20 + 光敏 + LCD | **数据汇聚 + 显示** | "VET6 主节点 + TFT LCD 实时显示" |
| 网关 | **ESP32-S3**（项目 A）| NRF24 + Wi-Fi | **协议转换 + 上云** | "异构网关：STM32 传感网 → ESP32 MQTT" |

### 为什么是"异构"而不是"3 块同板"

**面试官会问**："为什么不用 3 块同样的板子？"

**我们的答案**：
1. **真实工程就是异构的**：主节点（资源多）+ 子节点（低成本低功耗）+ 网关（高性能）
2. **资源合理利用**：VET6 100 个引脚用来接 1 个 DHT11 是浪费，C8T6 48 个引脚刚好
3. **演示更丰富**：3 块不同形态板子，面试展示视频视觉冲击更强
4. **简历可写**："**异构 STM32F103 多节点传感网（VET6 + C8T6 双平台）**"——这是**差异化亮点**

### 异构网络的协议兼容

- **节点端**：STM32F103 C8T6 / VET6 都用同一套 STM32 HAL 寄存器 API
- **节点 → 网关**：统一 NRF24L01+ 协议 + 自研二进制协议帧（帧头带节点 ID + 芯片型号）
- **网关 → 云**：统一 Wi-Fi + MQTT（与项目 A 复用 ESP-IDF 代码）

### D9 配套约束

- 节点固件用寄存器级（统一风格，方便调试）
- 主节点（VET6）演示用，可加更多传感器
- 子节点（C8T6）追求代码精简 + 低功耗

## D8 姿态传感器选型

| 候选 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| MPU6050 | 便宜（¥5）、资料多 | 6 轴裸数据，需自己融合 | ❌ |
| **GY-BNO055** | 9 轴 + 板载融合算法，直接出欧拉角 | 贵（¥40-80）| ✅ |
| MPU9250 | 9 轴但需自己融合 | 复杂度同 MPU6050 | ❌ |

**选 BNO055 的理由**：
- 用户已有 GY-BNO055（避免重复购买）
- 板载 Bosch 融合算法，**省去卡尔曼滤波 / DMP 移植**
- 直接读欧拉角寄存器，**驱动代码减少 50%**
- 简历可写"九轴姿态 + 板载融合算法应用"，**比 MPU6050 高级**

**B.2.2 设计调整**：
- 通信：I2C1（PB6/PB7），地址 0x28
- 数据：每 100ms 读一次欧拉角（roll/pitch/yaw）
- 任务优先级：同 B.2.1 DHT11
- 不需要：传感器融合代码（BNO055 内部完成）

## HAL 库获取方式（**不装 CubeMX 应用**）

从 ST 官网直接下源码包：
```
https://www.st.com/en/embedded-software/stm32cubef1.html
en.stm32cubef1.zip  → 解压得到 Drivers/STM32F1xx_HAL_Driver/
```

把 `Drivers/` 拷贝到对应工程即可。**CubeMX 应用绝不安装**。
