# 项目工作流：教学法 + 开工复盘

> **本文件目的**：把"如何高效推进项目"的方法沉淀下来。
>
> 1. **教学法**：每次讲一个新知识点，按下面 §A 的 6 步法来
> 2. **开工复盘**：每次启动一个新 Phase 任务前，按 §B 的模板先过一遍整个项目

---

## §A 教学法：6 步讲透一个知识点

> 适用于：B.1 寄存器、B.2 驱动、B.3 FreeRTOS、B.4 协议等任何硬核知识点

### Step 1: 🎯 先讲问题（为什么需要这个东西）

不要上来就讲怎么做。先说：
- **没有它会怎样？**（症状：乱码、跑飞、烧录失败...）
- **有了它能怎样？**（效果：72MHz 跑通、波特率正确...）
- **实际工程里谁会问你？**（面试官、debug 时你自己）

**示例**（SystemInit）：
> 上电后 MCU 跑 8MHz HSI，但我们代码假设 72MHz → 串口乱码 → 必须 main 之前配时钟。

### Step 2: 🌳 画一张架构图（时钟树 / 数据流 / 任务流）

**为什么要画图**：人脑对图的记忆是对文字的 6 倍。

**画图的规矩**：
- ASCII art 即可，不用花哨
- 关键路径加粗或加 emoji
- **标出每个节点的具体数字**（Hz / 字节 / 周期数）
- 框出"必须 / 不能"的硬限制

**示例**（STM32 时钟树）：
```
HSE 8MHz ──► PLL ×9 ──► SYSCLK 72MHz
                  ├── AHB /1 → 72MHz (CPU)
                  ├── APB1 /2 → 36MHz (I2C/USART2)
                  └── APB2 /1 → 72MHz (USART1/GPIO)
```

### Step 3: 🔍 逐行 / 逐段拆解代码

**原则**：
- **按"先后顺序"讲**，不要按代码里出现的顺序
- 每一步回答三件事：**做什么 / 为什么 / 坑在哪**
- 关键寄存器位要标**位号**（如 `RCC_CR bit16`）
- 涉及计算的，把**公式和代入过程**写出来

### Step 4: 🖼️ 总结图（全家福）

把全部步骤用一张图/表总结：
- 流程图（先后顺序）
- 或表格（步骤 → 作用 → 关键寄存器）

**好处**：面试时脑子里就这张图，复述用它。

### Step 5: ❓ 面试 Q&A 自检

**列出 5-6 个高频面试题**，每个给**简洁答案**（1-2 句话）。

**题目来源**：
- 你在 B 站/知乎/小红书看到的嵌入式面经
- 你自己想象面试官会怎么追问
- RM0008 / 数据手册里的常见考点

### Step 6: ✋ 动手验证（费曼学习法）

**强制要求**：
- 抄一遍寄存器定义到纸上（手写，不复制）
- 改一个小参数看会发生什么（破坏性实验）
- 给别人讲一遍（或者给我讲，让我假装是面试官提问）

**为什么**：听懂了 ≠ 会了。讲出来才知道哪里其实是蒙的。

## §B 开工复盘模板：每次新任务前先过一遍

> **强制流程**：开始任何 Phase N+1 任务前，**必须**先把整个项目在脑子里过一遍。
>
> 即使是接着上次的进度，也要重新过——因为人脑 24 小时会忘掉 70%。

### 模板（共 4 段）

#### B-1: 项目一句话（不超过 30 字）

> 3 个 STM32 节点采传感数据 → NRF24 → ESP32 网关 → OneNet 物联网云

#### B-2: 当前进度表（实时更新）

| Phase | 名称 | 状态 | 产物 |
|---|---|---|---|
| B.0 | 仓库骨架 + 决策 | ✅ | 9 个 commit，DECISIONS/BOM 完备 |
| B.1 | Hello UART + 72MHz | ✅ | 836B 编译通过，等烧录 |
| B.2.1 | DHT11 | ✅ | 940B 编译通过，等硬件 |
| B.2.2 | BNO055 | ✅ | 2052B 编译通过，等硬件 |
| B.2.3 | NRF24 | ⬜ | 待开始 |
| B.3 | FreeRTOS 3 任务 | ⬜ | 未开始 |
| B.4 | 自研协议 + CRC16 | ⬜ | 未开始 |
| B.5 | 组网 + OneNet | ⬜ | 未开始 |
| B.6 | 文档 + 简历素材 | ⬜ | 未开始 |

#### B-3: 决策锚点（5 秒回顾 D1-D9）

- **D1** Linux + VSCode + arm-none-eabi-gcc + OpenOCD
- **D2** 原生 FreeRTOS API（不装 CMSIS-RTOS）
- **D3** 协议大端
- **D4** CRC16-MODBUS（0xFFFF + 0xA001）
- **D5** 网关独立 `gateway/` 项目
- **D6** USB 5V + 板载 LDO
- **D7** B.1 寄存器 + B.2 混合 + **不装 CubeMX**
- **D8** 姿态传感器 = **GY-BNO055**（不是 MPU6050）
- **D9** 异构：2×C8T6（节点）+ 1×VET6（主）+ 1×ESP32-S3（网关）

#### B-4: 下一步要做什么（用 5W1H）

- **What**：具体写哪个文件？改哪个文件？
- **Why**：为什么现在做这个？（投入产出比 / 阻塞解除 / 简历加分）
- **Where**：哪个工程目录？
- **When**：预计耗时多少？
- **Who**：依赖谁？（自己 / 等硬件 / 等快递）
- **How**：用哪种方法？（寄存器级 / 抄现成 / 看参考手册哪一章）

#### B-5: 风险点（提前预警）

- 编译能过吗？
- 烧录需要什么硬件？
- 有没有阻塞前面 Phase 的坑？

## §C 实际操作 checklist（每次开工必跑）

```
□ 1. cat README.md 看进度表
□ 2. cat docs/DECISIONS.md 复习 D1-D9
□ 3. cat docs/BOM.md 看硬件状态
□ 4. git log --oneline | head -10 看最近做了什么
□ 5. git status 确认 working tree 干净
□ 6. 用 §B 模板过一遍整个项目
□ 7. 用 §A 教学法讲清楚要写的知识点
□ 8. 开始动手
```
